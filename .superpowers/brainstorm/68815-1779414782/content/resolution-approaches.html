Battle Resolution Animation — Approach Options

Simultaneous burst style, with distinct ability effects. All approaches use anime.js for orchestration.

What gets animated during resolution

🗡️ Gate Damage
  • Impact flash per gate
  • Floating damage numbers
  • HP bar drain
  • Gate breach indicator
🏴 Node Flips
  • Ownership flag swap
  • Trap detonation burst
  • Contest tug indicator
✨ Abilities
  • Siege Sword: slash arc
  • Stone Cloak: shield shimmer
  • Ember Blast: fire burst
  • Hex: purple corruption
  • Fortify: wall glow

Pick an approach

A

Overlay Burst (Recommended)

A semi-transparent animation overlay appears on top of the existing BattlefieldView for ~1.5s during resolution. All effects fire simultaneously — gate impacts, node flips, ability visuals, floating damage numbers — then the overlay fades and the updated state is revealed underneath.

Pros: Doesn't restructure existing components. Cinematic feel. Easy to skip.
Cons: Overlay positioning needs to match battlefield layout precisely.
B

Inline Component Animation

Each component (VaultDisplay, GateDisplay, NodeMap) gets its own animation state. When resolution data arrives, components animate internally — HP bars shake then drain, gates flash on impact, nodes pulse on flip. No overlay needed.

Pros: Each component owns its animation. Naturally responsive.
Cons: Harder to synchronize across components. Abilities need a separate layer anyway.
C

Hybrid — Overlay for effects, inline for state

Ability effects and floating damage numbers render on a positioned overlay. Gate/vault/node components animate their own state changes (HP drain, flag flip) in sync. An orchestrator hook coordinates timing so everything fires together.

Pros: Best of both — effects are decoupled from layout, state changes are native.
Cons: Most complex to implement. Needs a shared animation timeline.
